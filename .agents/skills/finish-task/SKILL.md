# 작업 마무리

worktree를 지우는 것과 작업을 끝내는 것은 다르다. 먼저 산출물과 검증을 남기고, 병합된 PR과 깨끗한 Git 상태가 확인될 때만 제거한다.

## 1. 완료 기준과 검증

- 시작 시 합의한 완료 기준을 하나씩 확인한다.
- 관련된 빌드·테스트·수동 확인을 실행하고 결과를 남긴다.
- `git status --short`와 `git diff --check`로 미커밋 변경과 공백 오류를 확인한다.
- 실패하거나 확인하지 못한 항목은 완료로 표시하지 않는다.

## 2. 산출물과 인계

다음 세션이나 리뷰어가 알아야 할 최소 정보만 정리한다.

- 변경한 내용과 이유
- 실행한 검증과 결과
- 남은 위험·후속 작업·막힌 항목
- 관련 커밋, PR, 이슈 번호

Orca comment에 현재 상태를 적는다.

```bash
orca worktree set --worktree <worktree-id> \
  --workspace-status <in-review|completed> \
  --comment "PR #123 생성; 테스트 통과; 병합 대기" \
  --json
```

## 3. 세션 교체

작업이 끝나지 않았지만 세션만 바꿔야 하면 worktree를 유지한다. 새 Claude Code 또는 Codex 터미널을 열고, 위 인계 내용만 첫 프롬프트에 넣는다. 이전 세션을 계속 재사용하지 않는다.

## 4. 안전한 정리

아래 조건을 모두 만족할 때만 제거 후보로 표시한다.

- PR이 기본 브랜치로 병합되었거나, 사용자가 PR 없이 폐기하기로 명시했다.
- `git status --short` 출력이 비어 있다.
- ignored 파일 중 보존해야 할 산출물이나 로컬 설정이 없는지 확인했다.
- 작업 브랜치의 필요한 커밋이 PR 또는 안전한 원격 브랜치에서 도달 가능한지 확인했다.
- 필요한 커밋·PR·검증 결과가 남아 있다.

제거는 되돌리기 어려운 동작이다. 자동으로 삭제하지 말고 사용자 확인 후 실행한다.

```bash
orca worktree rm --worktree <worktree-id> --run-hooks --json
```

`--force`는 사용자가 미병합 변경을 폐기하라고 명시적으로 확인한 경우에만 쓴다.
