# 말또 MVP 화면 명세

> Issue #21 산출물. `AGENTS.md`, `docs/PRD.md`, `docs/user-flow.md`, `docs/design/tokens.md`, `docs/architecture.md`를 구현 가능한 화면 명세로 옮긴다. 기존 문서의 **확정/제안** 상태를 변경하지 않는다.

## 1. 산출물과 사용법

- 시각 목업 원본: [`mockups.html`](mockups.html)
- 렌더링 검토본: [`mockups.png`](mockups.png)
- 검토 화면: iOS와 Android 각각 기본 글씨, Accessibility XL의 필수 8개 상태
- 구현 기준: Cupertino 스타일의 공통 Flutter View를 사용하고, 시스템 뒤로가기·최소 터치 영역만 플랫폼 규칙을 따른다.
- 목업 문자열은 직접 작성한 중립적 더미 문장이다. 앱에 기본 데이터로 탑재하지 않는다.
- 화면 이름과 상태는 후속 구현의 `View` 및 불변 `UiState` 이름에 바로 대응할 수 있도록 표기했다. 비즈니스 규칙은 View가 아니라 ViewModel/Repository/Domain에 둔다.

## 2. 화면과 전환

| ID | 구현 형태 | 한 가지 주 행동 | 진입 | 이탈 |
|---|---|---|---|---|
| R1 | `ScriptListView` | 대본 선택 | 앱 시작, 다른 화면 종료 | R2, O1 |
| R2 | `ScriptCreateView` | 대본 저장 | R1의 추가 | 저장·취소로 R1 |
| O1 | `ReadingSetupSheet` | 낭독 시작 | R1의 대본 선택 | 준비 성공은 R3, 취소는 R1, 실패는 O2 |
| R3 | `ReadingView.active` | 현재 어절 낭독 | 준비 성공 | 나가기는 R1, 완료는 같은 View의 완료 상태, 오류는 O3 |
| R3-C | `ReadingView.completed` | 목록으로 복귀 | 최종 회차 완료 | R1 |
| O2-P | `StartBlocked.permissionDenied` | 시스템 설정 열기 | 시작 검사 실패 | 설정 또는 R1 |
| O2-M | `StartBlocked.modelMissing` | 모델 준비 후 다시 확인 | 시작 검사 실패 | O1 또는 R1 |
| O3 | `RecognitionInterrupted` | 같은 위치에서 재시도 | 인식 중단·전경 복귀 | R3 또는 R1 |

`O1`, `O2`, `O3`는 새 라우트가 아니다. 시트 또는 현재 화면 위 안내로 표시하고, 열릴 때 접근성 포커스를 안내 제목으로 옮긴다. 닫히면 진입시킨 조작으로 돌려보낸다.

## 3. 공통 레이아웃 규칙

### 기본 글씨

- 화면 좌우 여백은 `space.4`(16), 섹션 사이는 `space.5`(24) 또는 `space.6`(32)를 사용한다.
- 주요 버튼은 가로 너비를 채우며 `target.preferred` 이상이다.
- iOS hit region은 최소 44×44pt, Android는 최소 48×48dp다. 목업에서는 공통 48 높이를 사용한다.
- 목록·본문처럼 내용이 길어지는 영역만 스크롤한다. 핵심 조작은 safe area 안에 고정한다.

### Accessibility XL 이상

- 글자 크기에 상한을 두지 않는다. 고정 높이 텍스트 컨테이너와 핵심 문구의 말줄임을 사용하지 않는다.
- 기본 글씨 화면과 같은 컴포넌트, 순서, 배치를 유지한다. XL 전용 컨트롤이나 별도 정보 구조로 바꾸지 않는다.
- 내비게이션의 좌우 조작은 기본 위치를 유지하고 글자만 확대한다. 실제 최댓값에서 제목과 충돌하면 제목 줄바꿈 또는 축약이 아닌 내비게이션 영역의 내용 기반 높이로 수용한다.
- 두 선택 버튼은 얼럿과 바텀시트에서도 가로로 유지한다. 각 버튼은 같은 너비와 최소 48 높이를 가지며 문구를 말줄임하지 않는다.
- 바텀시트·다이얼로그·낭독 하단의 `취소`와 `나가기`는 1px outline을 표시한다. 내비게이션 바에서는 테두리 없는 텍스트 버튼을 사용한다. 취소는 action blue, 나가기는 destructive red로 구분한다.
- 목록 행은 높이가 늘어나도 텍스트와 trailing 요소를 세로 중앙에 정렬한다.
- 다이얼로그는 글자 크기와 관계없이 화면 세로 중앙에 놓는다. 내용이 화면을 넘을 때는 다이얼로그 내부만 스크롤한다.
- 안내 본문이 길면 안내 내부가 스크롤되며 버튼은 같은 위치와 가로 배치를 유지한다.
- 낭독 화면은 상단 상태, 스크롤 가능한 대본, 하단 조작의 세 영역을 유지한다. 대본 영역이 최소 한 줄의 현재 어절을 보여주지 못하면 화면 전체를 세로 스크롤한다.
- Accessibility XXL·XXXL과 Android 200%에서도 같은 구조 유지 원칙을 적용한다. 가로 스크롤을 만들지 않는다.

## 4. 화면별 명세

### R1 대본 목록

**단일 행동:** 저장된 대본을 선택한다.

| 영역 | 컴포넌트·표시 | 동작·Semantics |
|---|---|---|
| 내비게이션 | 큰 제목 `대본`, 텍스트 버튼 `추가` | 추가: `새 대본 추가` |
| 목록 행 | 제목만 표시, 내용 기반 높이, disclosure 표시 | 전체 행이 탭 가능. `{제목}, 낭독 설정 열기` |
| 삭제 | iOS swipe action / Android에서도 동일 결과의 trailing 또는 길게 누르기 진입 | `대본 {제목} 삭제` 후 시스템형 확인. 삭제는 destructive 색 |
| 빈 상태 | `저장된 대본이 없습니다.`와 `대본 추가` | 샘플 본문을 표시하지 않음 |

Accessibility XL에서도 `추가`를 우측 상단에 유지하고 목록 제목을 여러 줄 허용한다.

### R2 대본 추가

**단일 행동:** 제목과 본문을 저장한다.

| 영역 | 컴포넌트·표시 | 동작·Semantics |
|---|---|---|
| 내비게이션 | blue 텍스트 `취소`, 제목 `대본 추가`, `저장` | 입력이 있으면 취소·시스템 뒤로에 폐기 확인(제안) |
| 제목 | 단일 행 입력, 라벨 `제목` | placeholder는 `제목을 입력하세요` |
| 본문 | 여러 줄 입력, 라벨 `본문` | placeholder는 `읽을 내용을 입력하세요`; 기본값 없음 |
| 검증 | 해당 필드 바로 아래 오류 | 공백뿐이면 저장하지 않음(제안), 첫 오류로 포커스 이동 |

Accessibility XL에서도 `취소`와 `저장`을 좌우 상단에 유지한다. 본문 입력은 고정 높이 대신 최소 높이만 두고 화면과 함께 스크롤한다.

### O1 낭독 시작 설정

**단일 행동:** 반복 횟수를 확인하고 시작한다.

| 영역 | 컴포넌트·표시 | 동작·Semantics |
|---|---|---|
| 시트 제목 | `낭독 시작` | 최초 접근성 포커스 |
| 대본 | `선택한 대본` 라벨과 제목 | 편집 기능 없음 |
| 반복 | 기본 1회, 1~10 선택(제안) | `반복 횟수, {값}회 선택됨` |
| 시작 | 하단 가로 행동 영역의 primary 버튼 | 준비 검사를 실행; 커서·회차는 준비 성공 전 만들지 않음 |
| 취소 | blue outline 보조 버튼 | 시트를 닫고 선택한 목록 행으로 포커스 복귀 |

목업은 현재 값과 증감 조작을 보이지만, 값 범위와 구체 컨트롤은 기존 문서처럼 제안 상태다. XL에서도 같은 반복 선택 컨트롤을 유지하며 글자와 터치 영역만 확대한다. `시작`과 `취소`도 글자 크기와 관계없이 가로로 배치한다.

### R3 낭독 중

**단일 행동:** 강조된 현재 어절을 소리 내어 읽는다.

시각 우선순위는 다음과 같이 고정한다.

1. 현재 어절: `type.reading.current`, indigo 캡슐, 가장 큰 본문 영역
2. 반복 횟수: `type.status`, 상단 독립 상태 행
3. 한 어절 뒤로: 하단의 되돌리기 아이콘 버튼
4. 나가기: 뒤로와 간격을 둔 red outline 보조 조작이며 전진 버튼처럼 보이지 않음

| 상태 | 시각 표현 | Semantics |
|---|---|---|
| 완료 어절 | 600 굵기 + system indigo 글자, 배경 없음 | `완료한 어절, {어절}` |
| 현재 어절 | 600 굵기 + indigo 캡슐 | `현재 어절, {어절}` |
| 대기 어절 | secondary label, 장식 없음 | `대기 중인 어절, {어절}` |

- 반복이 2회 이상일 때 `2/3회 · 2회 남음`처럼 현재/전체와 남은 횟수를 함께 읽을 수 있게 한다. 1회 표시 생략은 기존 제안 상태를 유지한다.
- `한 어절 뒤로`는 되돌리기 아이콘만 표시하되 48×48 이상의 터치 영역과 `한 어절 뒤로` Semantics 라벨을 제공한다. 이 버튼만 커서를 정확히 하나 줄이며, 첫 어절에서는 비활성 상태와 이유를 Semantics로 전달한다.
- 대본 탭·스크롤, 재시도, 나가기는 커서를 전진시키지 않는다.
- 현재 어절이 바뀔 때 읽을 수 있는 위치까지만 자동 스크롤한다. Reduce Motion에서는 즉시 위치를 바꾼다.
- `나가기`와 시스템 뒤로는 마이크·STT·구독을 정리한 뒤 R1로 간다.

### R3-C 완료

**단일 행동:** 목록으로 돌아간다.

- 같은 `ReadingView`의 상태 교체이며 별도 완료 라우트가 아니다(제안).
- `완료`, `3회 낭독했습니다.`, `목록으로`를 순서대로 표시한다.
- 진입 전에 마이크와 STT가 종료됐고 늦은 결과가 무시되는 것은 ViewModel/Repository의 전제다.
- 자동 복귀하지 않으며 경과 시간은 목업에 넣지 않는다. 경과 시간 표시는 기존 문서에서 제안이므로 구현 결정 전 우선순위를 높이지 않는다.

### O2-P 권한 거부

**단일 행동:** 시스템 설정을 연다.

- 제목 `마이크 접근이 필요합니다`, 원인, `설정 열기`, `나가기`를 표시한다. 두 행동은 가로로 같은 너비에 배치한다.
- 수동 전진이나 네트워크 인식 대체는 제공하지 않는다.
- 설정에서 돌아와도 자동 시작하지 않고 O1에서 사용자가 다시 시작한다(제안).

### O2-M 모델 미설치

**단일 행동:** 플랫폼의 모델 준비 절차를 진행한 뒤 다시 확인한다.

- 공통 제목은 `한국어 음성 모델이 필요합니다`다.
- iOS는 시스템이 제공하는 모델 준비 절차, Android는 기기 음성 인식 서비스의 한국어 모델 준비 절차라고 안내한다. 특정 설정 경로는 OS·제조사 차이로 목업에 고정하지 않는다.
- 주 행동 `다시 확인`, 보조 행동 `나가기`를 가로로 제공한다. 준비 전 낭독을 시작하지 않고 네트워크 STT로 전환하지 않는다.

### O3 인식 중단

**단일 행동:** 같은 위치에서 인식을 재시도한다.

- 제목 `음성 인식이 중단되었습니다`, `현재 위치는 그대로 유지됩니다.`를 표시한다.
- `재시도`와 `나가기`는 가로로 배치한다. `재시도`는 새 generation으로 인식을 시작하며 커서와 반복 횟수를 바꾸지 않는다.
- `나가기`는 세션을 종료하고 R1로 간다.
- 기존 STT 작업과 마이크를 먼저 중단하고, 늦은 결과를 폐기한 상태에서 안내를 표시한다.

## 5. 플랫폼 차이

| 항목 | iOS | Android |
|---|---|---|
| 최소 터치 영역 | 44pt, 공통 목업은 48pt | 48dp |
| 시스템 뒤로 | R2 내비게이션·제스처, R3는 자원 정리 후 pop | 시스템 back도 R3 나가기와 동일한 정리 수행 |
| 권한 거부 | 앱의 시스템 설정으로 이동 | 앱 권한 설정으로 이동 |
| 모델 준비 | iOS Speech asset 준비 상태 | on-device recognition support와 모델 상태 |
| 시각 언어 | 양쪽 모두 Cupertino 컴포넌트와 의미 색 | Cupertino 스타일 유지, 시스템 back 동작만 Android 규칙 준수 |

## 6. 구현 컴포넌트 경계

| 목업 요소 | 권장 View 컴포넌트 | 입력 상태·명령 |
|---|---|---|
| 목록 행 | `ScriptListTile` | `title`, `onSelected`, `onDelete` |
| 시작 시트 | `ReadingSetupSheet` | `scriptTitle`, `repeatCount`, `setRepeatCount`, `start`, `cancel` |
| 반복 상태 | `RepeatStatus` | `current`, `target`; 계산은 ViewModel 상태에서 제공 |
| 어절 본문 | `ReadingTranscript` / `ReadingWord` | 상태가 붙은 원문 범위 목록, 현재 범위 scroll key |
| 하단 조작 | `ReadingControls` | `canMoveBack`, `moveBackOneWord`, `leave` |
| 시스템 안내 | `ReadingBlockingNotice` | 정규화된 원인, `retry/openSettings/leave` |
| 완료 | `ReadingCompletion` | `completedCount`, `returnToList` |

View는 플랫폼 오류 코드, STT generation, matcher 임계값을 알지 않는다. `ReadingUiState`의 표시 가능한 상태와 명령만 사용한다.

## 7. 검토 결과

| 검토 항목 | 결과 | 후속 구현 확인 |
|---|---|---|
| Accessibility XL 레이아웃 | 기본 UI 구조를 유지하고 글자·터치 영역 확대와 필요한 줄바꿈·스크롤만 적용 | 실제 iOS 전 단계·Android 200%에서 스크린샷 비교 |
| 터치 영역 | 모든 목업 조작 48 logical px 이상 | 위젯 테스트에서 hit region 측정 |
| 어절 진행 우선순위 | 완료는 굵은 indigo, 현재는 indigo 캡슐, 대기는 회색 일반 글자로 왼쪽부터 채워지는 흐름 | 밝음/어두움/고대비와 흑백 확인 |
| 반복 횟수 우선순위 | 본문 위 독립 status 행, 현재/전체·남음 표시 | 1회 표시 생략 여부는 제안 상태 유지 |

| 오류 상태 | 원인·할 수 있는 행동·나가기를 한 안내 안에 배치 | 실제 시스템 설정/모델 준비 복귀 동작 확인 |
