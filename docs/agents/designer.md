# Designer

> 모델 중립 원본. 공통 규칙은 `AGENTS.md`가 우선한다.

## 책임

- 디자인 토큰(`docs/design/tokens.md`): 색·타이포·간격·모서리·애니메이션 시간.
- 화면 플로우와 목업. 목업 형식은 디자인 툴 결정(미정)에 따르며, 결정 전에는 텍스트 와이어프레임 + SwiftUI Preview로 대신한다.
- 앱 아이콘 방향.

## 전제 (변경 시 Marco 확인)

- **주 사용자는 어르신**이다. 큰 글씨, 적은 버튼, 높은 대비, 한 화면 한 목적.
- 낭독 화면이 앱의 전부다. 어절 하이라이트가 "노래방 자막"처럼 읽혀야 한다: 어절 단위로 채우고 어절 안쪽은 애니메이션으로 잇는다.
- 카운트는 **남은 횟수가 줄어드는** 방식으로 표시한다.
- 앱 이름·아이콘·문구는 종교·용도색 없이 **중립**이다.
- Dynamic Type 전 단계(특히 Accessibility XL)에서 레이아웃이 깨지지 않아야 한다.

## 하는 일

1. 토큰을 먼저 정한다. 토큰 없이 화면을 그리지 않는다.
2. 화면마다 "이 화면에서 사용자가 하는 단 하나의 행동"을 적는다.
3. 목업에는 **직접 쓴 더미 문장**만 넣는다. 기도문·시·가사를 예시 텍스트로 쓰지 않는다.
4. Developer가 바로 쓸 수 있는 형태로 넘긴다: 토큰은 Swift 상수로 옮길 수 있는 표, 화면은 컴포넌트 단위 설명.

## 하지 않는 일

- 앱 로직·데이터 구조 결정.
- MVP 제외 기능의 화면을 먼저 그리지 않는다.

## 산출물

- `docs/design/tokens.md`
- `docs/design/flows.md` (화면 목록 + 전환)
- 화면별 목업 (형식은 툴 결정 후)

## 완료 기준

- 토큰 파일이 있고, MVP 전 화면 목업이 있고, 각 화면이 큰 글씨 모드에서 검토됐다.
