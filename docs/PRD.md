# 말또 MVP 제품 요구사항

> Issue #14 산출물. 이 문서는 `AGENTS.md`와 `docs/requirements.md`를 제품 구현·QA 관점으로 구체화한다.
> 각 결정은 **확정** 또는 **제안**으로 표시한다. 제안은 Marco의 제품 방향 리뷰 전까지 확정으로 취급하지 않는다.

## 1. 제품 개요

### 문제 — 확정

사용자가 대본을 반복해서 소리 내어 읽을 때 현재 위치와 남은 반복 횟수를 스스로 추적해야 한다. 기존 문서 뷰어나 메모 앱은 사용자의 음성을 따라 현재 어절을 표시하지 않으므로, 시선을 놓치거나 반복 횟수를 잊기 쉽다.

### 해결 방식 — 확정

사용자가 직접 입력한 대본을 기기에만 저장하고, 온디바이스 한국어 음성 인식으로 낭독 위치를 따라가며 현재 어절을 강조한다. 마지막 어절까지 읽으면 한 회차를 완료하고, 목표 횟수만큼 같은 흐름을 반복한다.

### MVP 목표 — 확정

- 사용자가 별도 조작 없이 음성만으로 낭독 커서를 끝까지 진행한다.
- 현재 어절과 반복 상태를 큰 글씨에서도 놓치지 않는다.
- 잘못 진행됐을 때 한 어절 뒤로 안전하게 돌아간다.
- 대본과 음성을 서버로 보내거나 녹음 파일로 저장하지 않는다.
- iOS와 Android에서 같은 핵심 흐름을 제공한다.

### MVP 성공 조건 — 확정

- 직접 입력한 대본을 저장하고 앱 재실행 후 다시 선택할 수 있다.
- 지원되는 실제 iPhone과 Android 기기에서 네트워크 없이 한국어 부분 인식 결과가 낭독 커서를 진행시킨다.
- 1회 및 여러 회 반복 낭독을 끝까지 완료할 수 있다.
- 권한 거부, 모델·서비스 미지원, 인식 중단 상황에서 데이터 손실이나 임의 진행 없이 복구하거나 나갈 수 있다.
- 접근성 글자 크기에서 핵심 정보와 조작이 잘리거나 겹치지 않는다.

## 2. 대상 사용자와 사용 맥락

### 주요 사용자 — 확정

- 기억하거나 반복해서 읽고 싶은 대본을 직접 입력하는 사용자
- 읽는 위치를 자주 놓치거나 반복 횟수 추적에 도움을 원하는 사용자
- 큰 글씨, 단순한 화면, 명확한 상태 안내가 필요한 사용자를 포함

### 사용 맥락 — 제안

- 사용자는 기기를 손에 들거나 책상에 두고 전경 화면이 켜진 상태에서 낭독한다.
- 한 세션에서 하나의 대본만 낭독한다.
- 이어폰이나 외부 마이크는 플랫폼이 제공하는 입력 경로 범위에서 동작하되 MVP 별도 설정을 제공하지 않는다.

## 3. 제품 원칙

| 원칙 | 상태 | 제품 기준 |
|---|---|---|
| 음성으로만 전진 | 확정 | 탭·버튼·시간 경과로 낭독 커서를 앞으로 이동시키지 않는다. |
| 로컬 우선 | 확정 | 대본은 기기에만 저장하고, STT는 온디바이스 기능만 사용한다. |
| 최소 화면 | 확정 | 온보딩·계정·설정 탭을 만들지 않고 필요한 순간에만 안내한다. |
| 중립적 표현 | 확정 | 특정 종교·작품·용도에 치우치지 않는 이름과 문구를 사용한다. |
| 접근성 기본값 | 확정 | 큰 글씨와 보조 기술을 후속 보완이 아닌 기본 수용 기준으로 다룬다. |
| 동일한 핵심 경험 | 확정 | 플랫폼 API 차이는 어댑터에서 흡수하고 사용자 흐름은 양 플랫폼에서 같게 유지한다. |

## 4. MVP 범위

### 포함 — 확정

- 대본 제목·본문 직접 입력 및 로컬 저장
- 저장된 대본 목록, 선택, 삭제
- 반복 횟수 선택, 미선택 시 1회
- 현재·완료·대기 어절 구분과 자동 스크롤
- 음성 인식 결과에 의한 순방향 진행
- 한 어절 뒤로
- 현재 반복 회차 표시
- 낭독 나가기와 자원 정리
- 온디바이스 한국어 STT
- 권한·모델·서비스·인식 오류 안내와 재시도
- iOS·Android 접근성 글자 크기와 VoiceOver·TalkBack 지원

### 제외 — 확정

- 기본 탑재 대본 또는 제3자 콘텐츠
- 대본 편집
- 숙지 모드
- 대본 묶음과 파일 내보내기·가져오기
- OCR
- 통계·연속 기록·알림
- 대사 주고받기·가리기 게임
- 다국어
- 계정·로그인·서버·클라우드 동기화
- 앱 내 공유 갤러리
- iOS 18~25와 Android API 31~32 지원

제외 기능은 MVP 구현 Issue에서 다루지 않는다. 범위를 바꾸려면 별도 Issue와 Marco 확인이 필요하다.

## 5. 핵심 사용자 흐름 — 확정

1. 앱을 열면 저장된 대본 목록을 본다.
2. 대본이 없으면 추가 버튼으로 제목과 본문을 입력해 저장한다.
3. 목록에서 대본을 선택한다.
4. 반복 횟수를 선택한다. 아무것도 바꾸지 않으면 1회다.
5. 시작을 누르면 권한과 온디바이스 한국어 STT 준비 상태를 확인한다.
6. 준비되면 낭독 화면에서 음성을 인식하고 현재 어절을 순서대로 강조한다.
7. 필요하면 한 어절 뒤로 이동한다. 앞으로 이동하는 버튼은 없다.
8. 마지막 어절을 인식하면 현재 회차를 한 번만 완료한다.
9. 남은 회차가 있으면 이전 전사 결과를 폐기하고 첫 어절부터 다음 회차를 시작한다.
10. 모든 회차를 마치면 완료 상태를 표시한다. 사용자는 목록으로 돌아간다.
11. 어느 때든 나가기를 누르면 마이크와 STT를 중단하고 목록으로 돌아간다.

## 7. 낭독 세션 규칙

### 커서와 매칭 — 확정

- 대본은 원문 범위를 보존한 어절 단위로 처리한다.
- 인식 결과는 현재 위치 이후의 제한된 구간과만 비교한다.
- 부분 결과가 수정되거나 반복되어도 자동 진행 커서는 뒤로 가지 않는다.
- 명시적인 한 어절 뒤로 명령만 커서 후퇴를 허용한다.
- 중복 최종·부분 결과가 같은 어절이나 회차를 두 번 완료하지 않는다.
- 임계값과 정규화 규칙은 UI가 아니라 순수 Dart 매칭 엔진에 둔다.

### 반복 — 확정

- 현재 회차는 1부터 시작하고 목표 회차를 초과하지 않는다.
- 마지막 어절 완료 이벤트 하나가 현재 회차를 한 번 완료한다.
- 다음 회차를 시작할 때 이전 전사 구간을 폐기하거나 인식 세대를 교체한다.
- 최종 회차 완료 후 늦게 도착한 STT 결과는 상태를 바꾸지 않는다.

### 생명주기 — 확정

- 각 낭독 세션은 다른 세션과 구분 가능한 식별자 또는 동등한 종료 상태를 가진다.
- 나가기·완료·백그라운드 진입 시 Dart 구독과 네이티브 작업을 취소한다.
- 종료된 세션의 늦은 결과는 dispose된 화면이나 새 세션 상태에 반영하지 않는다.

## 8. 플랫폼 요구사항

### 공통 — 확정

- Flutter/Dart 단일 코드베이스와 Cupertino 스타일 UI를 사용한다.
- 부분 결과·최종 결과·오류·취소를 공통 STT 어댑터 계약으로 정규화한다.
- 음성·전사문·대본을 외부로 전송하거나 음성 파일로 저장하지 않는다.
- 네트워크 STT로 자동 대체하지 않는다.

### iOS — 확정

- 최소 iOS 26.0을 지원한다.
- `SpeechAnalyzer`와 `SpeechTranscriber`를 사용하는 네이티브 어댑터를 둔다.
- 권한, `ko-KR` 지원, 온디바이스 모델 준비 상태를 확인한다.
- 실제 iPhone 오프라인 검증을 출시 조건으로 둔다.

### Android — 확정

- 최소 Android 13/API 33을 지원하며 compileSdk·targetSdk는 36이다.
- on-device `SpeechRecognizer` 가용성과 `ko-KR` 지원 상태를 확인하는 네이티브 어댑터를 둔다.
- 실제 Pixel·Samsung 계열 기기의 비행기 모드 검증을 출시 조건으로 둔다.

### Android STT 채택 게이트 — 제안

- #12에서 한국어 부분 결과, 비행기 모드, 침묵 후 재개, 빠르거나 작은 목소리, 5분 이상 낭독을 실측한다.
- 시스템 STT가 핵심 흐름을 충족하면 그대로 채택한다.
- 충족하지 못한 경우에만 Vosk 같은 다운로드형 모델의 정확도·용량·라이선스·배포 방식을 비교한다.
- #12 결정 전에는 외부 STT 라이브러리를 제품 의존성으로 추가하지 않는다.

## 9. 비기능 요구사항

### 접근성 — 확정

- Flutter 텍스트 배율과 플랫폼 접근성 글자 크기를 지원한다.
- 큰 글씨에서 현재 어절, 반복 상태, 뒤로, 나가기가 잘리거나 겹치지 않는다.
- 최소 터치 영역은 iOS 44pt × 44pt, Android 48dp × 48dp다.
- 모든 조작과 상태에 의미 있는 Semantics 라벨·값을 제공한다.
- 색만으로 완료·현재·대기 상태를 구분하지 않는다.
- Reduce Motion 설정에서 불필요한 이동 애니메이션을 줄인다.

### 오프라인·안정성 — 확정

- 대본 추가·조회·삭제와 낭독 핵심 흐름은 네트워크 없이 동작한다.
- 5분 이상 낭독에서 비정상 종료, 자원 누수, 중복 완료가 없어야 한다.
- STT 오류가 대본 데이터를 변경하거나 삭제하지 않는다.
- 정량 지연·인식 품질 기준은 #12 결과와 기존 iOS POC 기록을 함께 비교해 확정한다.

### 개인정보 — 확정

- 서버, 계정, 로그인, 분석용 본문 수집을 사용하지 않는다.
- 사용자 대본·음성·전사문을 기기 밖으로 전송하지 않는다.
- 마이크 입력을 녹음 파일로 저장하지 않는다.
- 로그와 오류 정보에 대본·전사문을 포함하지 않는다.

### 저작권 — 확정

- 앱은 텍스트를 제공하지 않으며 모든 대본은 사용자가 직접 입력한다.
- 코드·테스트·프리뷰·문서·스크린샷에는 직접 작성한 더미 문장만 사용한다.
- 특정 출처에서 텍스트를 가져오거나 긁어오는 기능을 제공하지 않는다.
- 이름·아이콘·UI·스토어 문구를 특정 종교나 용도에 종속하지 않는다.

## 10. 출시 수용 기준

### 기능 — 확정

- #28~#31의 기능·오류·접근성 완료 기준이 양 플랫폼에서 충족된다.
- 음성 외 입력으로 낭독 커서가 전진하는 경로가 없다.
- 반복 경계와 종료 이후의 늦은 STT 결과가 상태를 오염시키지 않는다.

### 품질 — 확정

- `dart format`, `flutter analyze`, 전체 자동 테스트가 통과한다.
- Android와 iOS Debug 빌드가 같은 커밋에서 통과한다.
- 양 플랫폼 시뮬레이터·에뮬레이터의 기본 및 큰 글씨 화면을 확인한다.
- 실제 iPhone, Pixel, Samsung 계열 기기에서 오프라인 STT 핵심 시나리오를 확인한다.
- #33 QA 체크리스트의 P0·P1 항목이 모두 통과한다.

### 출시 차단 조건 — 확정

- 사용자 텍스트나 음성이 외부로 전송되거나 녹음 파일로 저장된다.
- 지원 대상 기기에서 온디바이스 한국어 STT 핵심 흐름을 제공할 수 없다.
- 권한·모델 오류가 앱 정지, 데이터 손실, 임의 커서 진행을 일으킨다.
- 큰 글씨에서 현재 어절이나 핵심 조작을 사용할 수 없다.
- 제3자 텍스트나 시크릿·개인정보가 앱 또는 Public 레포에 포함된다.

### 앱 이름과 식별자 — 확정

- 한국어 제품명과 한국어 스토어·앱 표시 이름은 `말또`로 한다.
- 한국어 이름은 "말하고, 또 말한다"는 반복 낭독 경험을 표현하며 특정 종교나 대본 용도에 연결하지 않는다.
- iOS Bundle ID와 Android applicationId는 `com.marcorable.maltto`를 사용한다.
- Flutter 프로젝트·패키지 이름은 `maltto`를 사용한다.
- MVP는 한국어만 지원하므로 영문·글로벌 표시 이름은 확정하지 않는다. 다국어 출시를 검토할 때 별도 Issue에서 시장별 이름과 상표를 다시 조사한다.
- 기술 식별자는 향후 표시 이름을 현지화하더라도 변경하지 않는다.

현재 #14 PRD 리뷰를 막는 신규 사용자 결정은 없다. Android STT 채택은 #12의 기술 검증 결과로 결정하며, 앱 아이콘과 개발자 계정은 각각 기존 `user` Issue #22·#9에서 출시 준비 전 확정한다.
