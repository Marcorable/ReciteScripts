# MVP 요구사항과 확정 결정

> Issue #13 산출물. `docs/PRD.md`를 작성하기 위한 입력이며, 이 문서의 각 항목은 **확정**, **제안**, **후속** 중 하나로 표시한다.

## 1. 제품 목표 — 확정

사용자가 직접 입력한 대본을 소리 내어 읽을 때 온디바이스 음성 인식이 현재 위치를 따라가며 어절을 강조한다. 대본 끝까지 읽으면 반복 횟수를 한 번 완료하고, 설정한 횟수만큼 같은 흐름을 반복한다.

MVP는 기능 수보다 다음 경험을 우선한다.

- 사용자가 읽고 있는 위치를 놓치지 않는다.
- 낭독 커서는 음성 인식으로만 앞으로 이동한다.
- 잘못 진행됐을 때 사용자가 버튼으로 한 어절 뒤로 갈 수 있다.
- 사용자 대본과 음성은 기기 밖으로 나가지 않는다.
- iOS와 Android에서 같은 핵심 흐름과 Cupertino 스타일을 제공한다.

## 2. 대상 사용자와 사용 맥락

### 확정

- 사용자는 기억하거나 반복해서 읽고 싶은 대본을 직접 입력한다.
- 큰 글씨, 적은 버튼, 높은 대비가 필요한 사용자를 포함한다.
- 네트워크 연결 없이도 핵심 낭독 기능을 사용할 수 있어야 한다.
- 앱과 스토어 문구는 특정 종교나 용도에 치우치지 않는다.

### 제안

- 한 손으로 기기를 들거나 책상에 둔 상태에서 낭독한다고 가정한다.
- 낭독 중 화면이 켜져 있는 전경 사용을 MVP 기준으로 한다.

## 3. 핵심 사용자 흐름 — 확정

1. 사용자가 대본 제목과 본문을 직접 입력해 저장한다.
2. 목록에서 저장한 대본을 선택한다.
3. 반복 횟수를 선택한다. 선택하지 않으면 1회다.
4. 시작하면 앱이 마이크·음성 인식 상태를 확인하고 낭독 세션을 연다.
5. 사용자의 음성과 일치한 어절까지 순서대로 강조하고 자동 스크롤한다.
6. 사용자는 필요할 때 한 어절 뒤로 이동할 수 있다.
7. 대본 끝에 도달하면 현재 반복을 완료한다. 남은 횟수가 있으면 처음부터 다음 반복을 시작한다.
8. 모든 반복을 마치거나 나가기를 누르면 낭독 세션을 종료한다.

“음성으로만 진행”은 **낭독 커서가 앞으로 이동하는 수단**을 뜻한다. 한 어절 뒤로와 나가기는 명시적인 버튼으로 제공한다. 앞으로 넘기기나 반복 완료를 수동으로 처리하는 버튼은 제공하지 않는다.

## 4. 기능 요구사항과 수용 기준

### SCR — 대본

| ID | 상태 | 요구사항 | 수용 기준 |
|---|---|---|---|
| SCR-01 | 확정 | 대본 추가 | 제목과 본문을 입력해 기기에 저장할 수 있다. 저장 후 목록에 나타난다. |
| SCR-02 | 확정 | 대본 목록 | 저장한 대본의 제목을 목록에서 보고 하나를 선택할 수 있다. 기본 탑재 대본은 없다. |
| SCR-03 | 확정 | 대본 삭제 | 사용자가 저장한 대본을 기기에서 삭제할 수 있다. |
| SCR-04 | 확정 | 로컬 저장 | 앱을 종료하고 다시 열어도 대본이 남는다. 서버나 계정 동기화를 사용하지 않는다. |
| SCR-05 | 제안 | 입력 검증 | 공백뿐인 제목·본문은 저장하지 않고 같은 화면에서 이유를 안내한다. |
| SCR-06 | 후속 | 대본 편집 | MVP 범위에 포함하지 않는다. 필요성은 출시 후 피드백으로 판단한다. |

### SET — 낭독 시작 설정

| ID | 상태 | 요구사항 | 수용 기준 |
|---|---|---|---|
| SET-01 | 확정 | 반복 횟수 선택 | 사용자가 낭독 시작 전에 반복 횟수를 선택할 수 있다. |
| SET-02 | 확정 | 기본값 1회 | 별도 선택 없이 시작하면 목표 반복 횟수는 1회다. |
| SET-03 | 제안 | 단순한 입력 방식 | 숫자 직접 입력보다 실수를 줄이는 Cupertino 스타일 선택 UI를 우선한다. 허용 범위는 #14에서 정한다. |

### READ — 낭독 세션

| ID | 상태 | 요구사항 | 수용 기준 |
|---|---|---|---|
| READ-01 | 확정 | 현재 위치 강조 | 음성 인식 결과와 순서대로 일치한 어절을 노래방 가사처럼 구분해 표시한다. |
| READ-02 | 확정 | 앞으로만 자동 진행 | 새 인식 결과는 현재 커서 이후 어절과만 비교하며, 음성 인식 외 입력으로 커서를 앞으로 이동시키지 않는다. |
| READ-03 | 확정 | 자동 스크롤 | 현재 어절이 화면에서 읽을 수 있는 위치에 유지되도록 스크롤한다. |
| READ-04 | 확정 | 현재 반복 표시 | 목표 횟수가 2회 이상이면 현재 횟수와 전체 횟수를 함께 표시한다. 1회일 때 표시 여부는 #15에서 정한다. |
| READ-05 | 확정 | 한 어절 뒤로 | 버튼을 한 번 누르면 현재 커서가 정확히 한 어절 뒤로 이동한다. 첫 어절에서는 더 뒤로 가지 않는다. |
| READ-06 | 확정 | 반복 전환 | 마지막 어절을 인식하면 현재 반복을 완료한다. 남은 횟수가 있으면 이전 반복의 전사 결과를 폐기하고 새 인식 세대로 전환한 뒤, 커서를 첫 어절로 되돌리고 다음 횟수를 표시한다. |
| READ-07 | 확정 | 나가기 | 나가기를 누르면 STT 구독과 네이티브 작업을 포함한 마이크·STT 처리를 즉시 중단하고 낭독 화면을 벗어난다. 종료된 세션에 뒤늦게 도착한 결과는 세션 식별자 또는 종료 상태로 폐기하며 현재·새 세션의 상태를 변경하지 않는다. |
| READ-08 | 제안 | 자동 스크롤 안정성 | 현재 어절이 바뀔 때만 필요한 만큼 이동하고 불필요한 화면 점프를 만들지 않는다. |

### STT — 온디바이스 음성 인식

| ID | 상태 | 요구사항 | 수용 기준 |
|---|---|---|---|
| STT-01 | 확정 | 플랫폼 STT API 선택 | iOS 26+는 `SpeechAnalyzer`·`SpeechTranscriber`, Android API 33+는 on-device `SpeechRecognizer`를 플랫폼 API로 선택한다. Android 한국어 인식 품질과 오프라인 동작의 수용 여부는 #12 결과에 따라 결정한다. |
| STT-02 | 확정 | 외부 전송 금지 | 사용자 음성·전사문·대본을 네트워크, 서버, 분석 도구로 보내지 않는다. |
| STT-03 | 확정 | 녹음 미저장 | 마이크 입력은 실시간 처리에만 사용하며 음성 파일로 저장하지 않는다. |
| STT-04 | 확정 | 부분 결과 | 최종 문장이 끝날 때까지 기다리지 않고 사용 가능한 부분 결과로 현재 어절을 갱신한다. |
| STT-05 | 확정 | 플랫폼 격리 | Flutter UI와 Dart 도메인은 네이티브 STT 구현을 직접 참조하지 않고 공통 어댑터 계약만 사용한다. 어댑터는 부분 결과·최종 결과·오류·취소 이벤트의 의미와 전달 순서를 양 플랫폼에서 동일하게 정규화한다. |
| STT-06 | 후속 | Android 대안 엔진 | 시스템 STT가 #12의 오프라인·지연 기준을 충족하지 못할 때만 Vosk 같은 다운로드형 모델을 비교한다. |
| STT-07 | 후속 | 하위 OS 지원 | iOS 18~25와 Android API 31~32는 출시 후 별도 호환 어댑터로 확장한다. |

## 5. 예외 상태와 기대 동작

| 예외 상태 | MVP 기대 동작 | 분류 |
|---|---|---|
| 마이크 권한 미결정 | 시스템 권한 요청 전에 사용 이유를 짧게 안내한다. | 제안 |
| 마이크·음성 인식 권한 거부 | 낭독을 시작하지 않고 설정에서 권한을 바꾸는 방법과 나가기를 제공한다. 수동 전진 폴백은 제공하지 않는다. | 확정 |
| 한국어 또는 온디바이스 모델 사용 불가 | 낭독을 시작하지 않고 원인을 안내한다. 지원 여부를 숨긴 채 네트워크 STT로 전환하지 않는다. | 확정 |
| STT가 일시 중단되거나 오류 발생 | 커서와 반복 상태를 유지하고 재시도 또는 나가기를 제공한다. 오류 때문에 반복을 완료 처리하지 않는다. | 제안 |
| 앱이 백그라운드로 이동 | 마이크와 STT를 중단한다. 복귀 시 자동 재개하지 않고 사용자가 재시도한다. | 확정 |
| 인식되지 않는 말·침묵 | 커서를 이동하지 않는다. 일정 시간 후에도 임의로 다음 어절을 완료하지 않는다. | 확정 |
| 대본 마지막 어절의 중복 부분 결과 | 같은 반복을 한 번만 완료한다. | 확정 |
| 사용자가 첫 어절에서 뒤로 누름 | 상태를 바꾸지 않는다. | 확정 |
| 사용자가 낭독 중 나감 | 현재 세션을 종료한다. 진행 기록 보존은 MVP에 포함하지 않는다. | 제안 |
| 저장된 대본이 없음 | 빈 목록 안내와 대본 추가 진입점만 표시한다. 샘플 대본을 제공하지 않는다. | 확정 |

## 6. 비기능 요구사항 — 확정

### 접근성

- Flutter 텍스트 배율과 플랫폼 접근성 글자 크기를 지원한다.
- 큰 글씨에서 핵심 버튼과 현재 어절이 잘리거나 겹치지 않는다.
- 터치 영역은 iOS에서 최소 44pt × 44pt, Android에서 최소 48dp × 48dp를 확보한다.
- 버튼과 상태에는 의미 있는 Semantics 라벨을 제공한다.
- 색만으로 읽은 어절과 현재 어절을 구분하지 않는다.

### 오프라인·성능

- 핵심 흐름은 네트워크 연결 없이 동작한다.
- STT 지연과 정확도 목표값은 기존 iOS POC와 #12 Android 스파이크 결과를 근거로 #14에서 정한다.
- 5분 이상 낭독에서 중단·메모리 누수·비정상적인 배터리 소모가 없는지 #12와 QA 단계에서 확인한다.

### 개인정보·저작권

- 앱은 대본을 제공하지 않는다. 모든 대본은 사용자가 자기 기기에 직접 입력한다.
- 제3자 기도문·경전·가사·시를 코드, 테스트, 프리뷰, 문서, 스크린샷에 넣지 않는다.
- 특정 출처에서 텍스트를 가져오거나 긁어오는 기능을 만들지 않는다.
- 사용자 대본과 음성은 기기 밖으로 나가지 않는다.
- 음성을 녹음 파일로 저장하지 않는다.
- 앱 이름·아이콘·UI·스토어 문구는 특정 종교나 용도에 치우치지 않는다.

## 7. 플랫폼과 개발 결정

### 확정

- 한국어 제품명·스토어명·앱 표시 이름 `말또`
- iOS Bundle ID·Android applicationId `com.marcorable.maltto`, Flutter 프로젝트명 `maltto`
- 글로벌 표시 이름은 다국어 출시 검토 시 별도 Issue에서 결정
- Flutter/Dart 단일 코드베이스
- Android Studio 주 IDE, Xcode 병행
- 양 플랫폼에 Flutter Cupertino 스타일 적용
- iOS deployment target 26.0
- Android minSdk 33, compileSdk·targetSdk 36
- 로컬 저장, 서버·로그인·클라우드 동기화 없음
- Flutter feature-first 구조와 `View → ViewModel → Repository → Service` 의존 방향
- Pigeon 네이티브 브리지와 drift + SQLite 저장. 상세 계약과 마이그레이션 전략은 `docs/architecture.md`를 따름
- 프로젝트 밖에서도 재사용 가능한 Flutter 개발 규칙은 실제 적용으로 검증한 뒤 `marcorable-kit`에 정리
